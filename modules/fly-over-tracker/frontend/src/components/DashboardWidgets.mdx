# Dashboard widgets

Five self-sufficient, embeddable widgets for a dashboard (e.g. `homesweethome`). Each
one is configured entirely through props — a location, a radius, and an auto-refresh
cadence — and fetches and refreshes its own data, so the host application needs no data
wiring.

## Installation

```bash
pnpm add @sousa99/fly-over-tracker-components
```

The package publishes **only these five widgets**. It relies on the peer dependencies
`react`, `react-dom`, `leaflet`, and `react-leaflet`, and ships its own Tailwind styles:

```tsx
import '@sousa99/fly-over-tracker-components/styles.css';
```

## FlyOverWidget

A map of the configured location with the aircraft in range listed beneath it (compact
cards). Fills the available width; the map expands to the available height and the list
takes its natural height. Use `maxResults` to cap the list.

## Shared configuration

All widgets share these props:

| Prop          | Type                           | Default | Description                                        |
| ------------- | ------------------------------ | ------- | -------------------------------------------------- |
| `location`    | `{ lat, lng, radiusKm }`       | —       | The location and radius to watch                   |
| `autoRefresh` | `'off' \| 5 \| 10 \| 30 \| 60` | `'off'` | Seconds between automatic refreshes                |
| `baseUrl`     | `string`                       | `''`    | Module backend base URL; `''` = same-origin `/api` |
| `className`   | `string`                       | —       | Extra classes on the widget root                   |

`FlyOverWidget`, `FlyOverListCard`, and `FlyOverClosestPanel` additionally accept
`maxResults?: number` to cap their lists (omit to list all). The map-rendering widgets
(`FlyOverWidget`, `FlyOverMapCard`) additionally accept `tileUrl?: string` to override the
default OpenStreetMap basemap (Leaflet `{z}/{x}/{y}` placeholders) and `debug?: boolean` to
log layout/tile diagnostics to the console.

See each widget's page for the full props reference, live examples, and behavior notes.

## Status bar

Every widget renders the **standardized status bar** above its content — the same shared
component (`WidgetStatusBar` from the internal `@sousa99/homesweethome-components` package)
used across all Home Sweet Home modules, so wording, layout, and behavior are identical by
construction:

- **`Last updated {YYYY-MM-DD HH:MM:SS <zone>}`** — the device-local full timestamp (date, 24-hour
  time, and timezone) of the last successful load; shows **`Not updated yet`** before the first load
  completes.
- **`Updating…`** — a transient indicator (with a polite live region) shown only while a
  refresh is in flight.
- **`Refresh`** — a manual refresh button (disabled while updating).
- A **failure notice** (`role="alert"`) when the latest load failed — the last successful
  time stays visible and `Refresh` retries.
